# 1. `ProviderScope`

Di `main.dart`:

```dart
void main() => runApp(
  const ProviderScope(
    child: MyApp(),
  ),
);
```

Ini bagian **WAJIB banget** untuk Riverpod.

### `ProviderScope`

Tempat Riverpod menyimpan dan mengelola **provider/state**.

Gampangnya:

```text
ProviderScope
      │
      └── MyApp
           ├── TodoPage
           └── widget lain
```

Semua widget di bawah `ProviderScope` bisa mengakses provider Riverpod.

Kalau provider itu seperti **lemari penyimpanan state**, `ProviderScope` adalah **ruangan yang menyediakan sistem lemari tersebut**.

# 5. `copyWith`

Ini salah satu nama yang perlu kamu ingat.

```dart
Todo copyWith({String? title, bool? done}) =>
    Todo(
      title ?? this.title,
      done: done ?? this.done,
    );
```

Tujuannya:

> **membuat Todo baru berdasarkan Todo lama, tetapi boleh mengganti beberapa property.**

Misalnya ada:

```dart
Todo(
  'Belajar Flutter',
  done: false,
)
```

Kita mau mengubah `done` menjadi `true`.

Daripada mengubah object lama:

```text
Todo lama
title = Belajar Flutter
done = false
```

kita buat:

```text
Todo baru
title = Belajar Flutter
done = true
```

dengan:

```dart
todo.copyWith(done: true);
```

---

# 6. `String?` dan `bool?`

Kenapa ada tanda `?`

```dart
String? title
bool? done
```

`?` berarti nilai tersebut **boleh null**.

Jadi:

```dart
String
```

tidak boleh null.

Sedangkan:

```dart
String?
```

boleh:

```text
"Belajar"
```

atau:

```text
null
```

Kenapa `copyWith` menggunakan nullable?

Karena kita perlu membedakan:

> "property ini mau diganti"

dengan:

> "property ini tidak mau diganti."

---

# 7. `??`

```dart
title ?? this.title
```

`??` artinya:

> Kalau yang kiri **tidak null**, gunakan yang kiri. Kalau null, gunakan yang kanan.

Contoh:

```dart
title = "Makan"
```

maka:

```dart
title ?? this.title
```

hasilnya:

```text
"Makan"
```

Tapi kalau:

```dart
title = null
```

maka:

```text
this.title
```

yang digunakan.

Jadi:

```dart
Todo(
  title ?? this.title,
  done: done ?? this.done,
)
```

berarti:

> "Pakai nilai baru kalau diberikan, kalau nggak, pertahankan nilai lama."

---

## Terus `...state` apaan?

```dart
[...state, Todo(title)]
```

`...` disebut **spread operator**.

Misalnya state sekarang:

```text
[
  Todo A,
  Todo B
]
```

Maka:

```dart
[...state, Todo C]
```

menjadi:

```text
[
  Todo A,
  Todo B,
  Todo C
]
```

Yang penting:

**kita tidak mengubah list lama.**

Kita membuat **list baru**.

---

# 12. Kenapa nggak boleh `state.add()`?

Karena ini:

```dart
state.add(Todo(title));
```

mengubah list yang sama.

Riverpod mengandalkan perubahan state untuk mengetahui bahwa UI perlu diperbarui.

Lebih aman:

```dart
state = [...state, Todo(title)];
```

Jadi:

```text
list lama
   ↓
buat list baru
   ↓
state = list baru
   ↓
Riverpod tahu state berubah
   ↓
UI rebuild
```

Ini disebut **immutability**.

# 14. `remove`

```dart
void remove(int index) => state = [...state]..removeAt(index);
```

Tujuannya menghapus Todo.

Ada sedikit sintaks Dart yang ngeselin di sini 😭:

```dart
..removeAt(index)
```

`..` disebut **cascade operator**.

Secara konsep:

```dart
final todos = [...state];
todos.removeAt(index);
state = todos;
```

kurang lebih itulah yang dilakukan.

Jadi:

```dart
[...state]..removeAt(index)
```

artinya:

> buat list baru → hapus item pada index tersebut → gunakan list itu sebagai state.

# 18. `ref.watch`

```dart
final todos = ref.watch(todoListProvider);
```

Artinya:

> "Ambil state dari `todoListProvider`, dan **pantau perubahannya**."

```text

```

```text

```


```text

```

```dart

```



# 🧠 BESAR BANGETNYA: Riverpod itu sebenarnya begini

Kalau kamu cuma menghafalkan kode, nanti pas dosen ganti satu baris kamu:

**🧍‍♀️:** "kenapa semuanya mati." 😭

Jadi pahami 4 komponen ini:

```text
                RIVERPOD
                   │
        ┌──────────┴──────────┐
        │                     │
     Provider              Notifier
        │                     │
 "tempat akses state"    "pengelola state"
        │                     │
        └──────────┬──────────┘
                   ↓
                 State
                   │
                   ↓
              UI / Widget
```

Dalam kodemu:

```text
todoListProvider
       ↓
NotifierProvider
       ↓
TodoListNotifier
       ↓
List<Todo>
       ↓
TodoPage
```

Dan interaksinya:

```text
                    TodoListNotifier
                    ┌──────────────┐
                    │ state        │
                    │ [Todo, Todo] │
                    │              │
                    │ add()        │
                    │ toggle()     │
                    │ remove()     │
                    └──────┬───────┘
                           │
                  todoListProvider
                           │
             ┌─────────────┴─────────────┐
             ↓                           ↓
        ref.watch()                 ref.read()
             ↓                           ↓
        ambil state              ambil notifier
        + dengarkan              untuk menjalankan
        perubahan                add/toggle/remove
             │
             ↓
             UI
```

### Kalau buat ujian, kata kuncinya:

| Istilah            | Arti gampang                                    |
| ------------------ | ----------------------------------------------- |
| `ProviderScope`    | Wadah agar Riverpod tersedia                    |
| `Provider`         | Penyedia state/data                             |
| `Notifier`         | Pengelola state                                 |
| `state`            | Data yang sedang dikelola                       |
| `NotifierProvider` | Penghubung Notifier dengan UI                   |
| `ConsumerWidget`   | Widget yang bisa memakai Riverpod               |
| `WidgetRef`        | Alat untuk mengakses provider                   |
| `ref.watch()`      | Ambil + dengarkan perubahan                     |
| `ref.read()`       | Ambil tanpa mendengarkan perubahan              |
| `.notifier`        | Mengakses pengelola state                       |
| `copyWith()`       | Membuat object baru dengan perubahan tertentu   |
| `...state`         | Menyalin isi list ke list baru                  |
| `immutability`     | Tidak mengubah object/list lama secara langsung |

**Dan konsep inti Week 3 ini kemungkinan besar adalah:**

> **State management menggunakan Riverpod, dengan prinsip immutability agar perubahan state dapat dideteksi dan UI melakukan rebuild.**

Jadi bedanya dengan kode `go_router` sebelumnya:

```text
go_router
→ "GIMANA PINDAH HALAMAN?"

Riverpod
→ "GIMANA DATA YANG DIPAKAI BANYAK WIDGET DIATUR DAN DIUPDATE?"
```

Dua-duanya sama-sama package tambahan, tapi problem yang mereka selesaikan **beda total**. Flutter memang hobi memberi manusia 17 istilah untuk sesuatu yang pada dasarnya cuma "pindah halaman" dan "ngurus data". 😭✊
